	\texttt{fancyqr} is a simple package to create fancy qr-codes with the help of the \textit{\href{https://www.ctan.org/pkg/qrcode}{qrcode}}-package.
	You can use the |\fancyqr|-macro as a drop-in replacement for the normal |\qrcode|.\footnote{\ltx{\\fancyqr[<qr-options>]\{<url>\}}}

	To hide a center square -- for an image, say -- |\FancyQrDoNotPrintSquare{<x>}{<y>}| blanks a rectangle of radius x and y around the center, and |\FancyQrDoNotPrintRadius{<factor>}| \href{https://github.com/EagleoutIce/fancyqr/pull/41}{rounds} it.
	Its cut corners are rounded by the default |\FancyQrRoundCut|; |\FancyQrHardCut| leaves them sharp.
	|\FancyQrSeed{<n>}| (or the |seed| option) fixes the \LaTeX\ seed the randomized styles draw from.

	\autoref{tbl:extra-keys} shows every extra qr-option; |\fancyqrset{<keys>}| sets them outside a call.
	The defaults:
\begin{lstlisting}
\fancyqrset{image padding=0,gradient=true,
	gradient angle=135,
	r color=red!68!black!88!white!90!white,
	l color=purple!40!red!20!black!90!white}
\end{lstlisting}
	Some examples (using \href{https://www.ctan.org/pkg/fontawesome}{fontawesome}; images work just as well):

\begin{tcblisting}{}
\fancyqr[
   classic,image=\LARGE\faGithub,
]{https://github.com/EagleoutIce/fancyqr}
\end{tcblisting}
\begin{tcblisting}{}
\FancyQrLoad{goo}%
\fancyqr[
   seed=3,content color=black
]{https://github.com/EagleoutIce/fancyqr}%
\end{tcblisting}
\begin{tcblisting}{}
% needs \usepackage[prefix=@]{xcolor-material}
\FancyQrLoad{dots}%
\fancyqr[
   height=4cm,
   image={\textbf{\textcolor{gray}{fancy}qr}},
   random color={@Red800}{@Purple800}{@Indigo800}{@Teal800}{@Green800}
	{@DeepOrange800}{@Brown700}{@BlueGrey700}
]{https://github.com/EagleoutIce/fancyqr}%
\end{tcblisting}

\section{Styles}\label{sec:styles}

	Besides |default| there are eight styles, loaded (locally) with |\FancyQrLoad{<name>}|; |\FancyQrLoad{default}| or |\FancyQrLoadDefault| resets.
	\autoref{fig:styles} shows them all with the same payload and the call that produced it.

\begin{figure}[H]
	\centering
	\newcommand*\ShowStyle[1]{%

			\fancyqr[height=2.6cm,tight,seed=4]{https://github.com/EagleoutIce/fancyqr}%
			\\[.5ex]\texttt{\textbackslash FancyQrLoad\{#1\}}
		\end{minipage}}
	\ShowStyle{default}\hfill\ShowStyle{rounded}\hfill\ShowStyle{flat}\\[2ex]
	\ShowStyle{frame}\hfill\ShowStyle{dots}\hfill\ShowStyle{blobs}\\[2ex]
	\ShowStyle{glitch}\hfill\ShowStyle{glows}\hfill\ShowStyle{goo}%
	\FancyQrLoadDefault
	\caption{Every style that \texttt{fancyqr} ships with, the randomized ones (\texttt{blobs}, \texttt{glitch}, \texttt{goo}) with a fixed \texttt{seed}. All but \texttt{frame} are read by a scanner as they are: its outlined patterns are not, so it needs \texttt{finder=square}.}
	\label{fig:styles}
\end{figure}

	The |default| style rounds the free corners of a tile with the |rounding| radius.
	A corner enclosed by two black neighbours but not by the diagonal one is an \emph{inner} corner and gets a fillet of the smaller |inner rounding| radius instead of a hard 90 degree edge.
	|inner rounding=0|, or the |rounded| style, brings back the sharp notches of earlier versions:

\begin{tcblisting}{}
\fancyqr[
   color=black,inner rounding=0
]{https://github.com/EagleoutIce/fancyqr}
\end{tcblisting}
\begin{tcblisting}{}
\fancyqr[
   color=black,rounding=.25,inner rounding=.35
]{https://github.com/EagleoutIce/fancyqr}
\end{tcblisting}

	|frame| outlines the shape the modules form -- only the sides facing white are stroked, so a run of modules becomes one pill -- and puts a dot inside every module, because that is where a scanner samples.
	|goo| hangs its tiles downwards by |\fancyqr@goo@drip|, |0| makes it symmetric again.
	|glows| and |glitch| draw every module more than once, which a style asks for with |\FancyQrPasses{<n>}|: |glows| once per halo ring, |glitch| for the two displaced ghosts behind its shards, where |\fancyqr@glitch@detach| is the chance that a shard tears off a neighbour instead of merging with it.
	The halos are tuned with |\FancyQrGlow{<width>}{<strength>}{<falloff>}| -- the width of the widest ring in modules, the percentage of color it keeps, and how quickly the rings gain color towards the tile -- and with |\FancyQrGlowColor{<from>}{<to>}|, where |.| is the color of the tile they surround, so |\FancyQrGlowColor{white}{black}| makes a white backglow.
	Keep the width below one module, or the halos of two modules separated by a white one run into each other.

	|dots| and |blobs| draw the position and alignment patterns as solid |circle|s, because a scanner has to find those first and made of tiles they are not found; the other styles leave them to their tiles.
	Only |default| and |glows| understand inner corners; a style declares that with |\FancyQrInnerRoundings|, or opts out with |\FancyQrNoInnerRoundings|, so the others do not pay for the lookups.

\section{Position and alignment patterns}\label{sec:finder}

	The three big position (finder) patterns and all alignment patterns can be drawn as one shape instead of as single modules: |finder| picks the shape of the ring, |finder core| that of the center block, |finder radius| and |finder thickness| the corner radius and the width of the ring, and \autoref{fig:finder} combines them.
	|finder color| paints those patterns and |content color| everything else, so |content color=black| keeps the gradient on the patterns alone.

	The modules of a pattern stay black in the matrix and only their drawing is replaced, so neighbouring tiles still merge into the shape wherever it allows it.
	A |finder thickness| other than |1| leaves the 1:1:3:1:1 run a scanner looks for, so check that the code still reads.
	The default |finder=inherit| (synonym |none|) leaves the patterns to the tiles of the loaded style; loading a style resets |finder| and |finder core|, because a style owns its shapes.

\ForVersion{2.4}{2026-08-17}{
	\item Weakly rounded (negative) inner corners for the \texttt{default} style
	\item New \texttt{rounded}, \texttt{glows} and \texttt{goo} styles
	\item Style the position and alignment patterns (\texttt{finder}, \texttt{finder core}, \texttt{finder color}, \texttt{finder radius}, \texttt{finder thickness}) and color them apart from the data with \texttt{content color}
	\item Configurable \texttt{rounding} and \texttt{inner rounding}, reproducible randomness with \texttt{seed}, a less red default gradient
	\item Roughly five times faster (the module matrix of a code is kept, see \texttt{cache}), an \texttt{l3build} test suite
	\item Tile overlap is relative to the module size (\texttt{overlap}), which keeps renderers from leaving seams between the tiles
	\item Bug fixes: \texttt{frame} is readable by a scanner again, the center module is no longer dropped without a cut-out, \texttt{gradient angle} is read in degrees again, and an embedded image is centered exactly
}
